# Адаптивна фара та система аварійної сигналізації

> Покрокова практика: емулюємо бортову систему авто на ESP32-S3. Фара сама вмикає
> «ближнє світло» в тунелі (фоторезистор), а «датчик удару» (кнопка) миттєво
> запускає аварійну сигналізацію — синхронне блимання помаранчевих LED. На
> логічному аналізаторі досліджуємо тривалість сигналу, меандр блимання та
> апаратний антидребезг конденсатором 0.1 мкФ. Увесь код готовий до заливання.

**🧩 4 кроки з кодом  ·  📟 Аналіз сигналів  ·  🏆 Челенджі**

*Фінальний міні-проєкт до Модуля 1. Інтегрує Уроки 1.1 (RLC/конденсатор), 1.2 (LED/опір), 1.3 (Blink/меандр), 1.4 (Datasheet/Pull-up), 1.5 (кнопка/сигнали), 1.6 (ADC).*

## 01 · Підготовка: обладнання, схема, проєкт
**15 ХВИЛИН · ПІДКЛЮЧАЄМО ТА ПЕРЕВІРЯЄМО**

### Крок 0 · Обладнання та схема ⏱ 15 хв

**Що на столі:** ESP32-S3 N16R8 (Type-C) + кабель **даних**, макетна плата MB-102, перемички, фоторезистор (LDR) + резистор **10 кОм** (дільник ADC), **білий** LED + 330 Ом (ближнє світло), **2 помаранчеві** LED + 2×330 Ом (аварійка), тактова кнопка (датчик удару), конденсатор **0.1 мкФ** (апаратний debounce), логічний аналізатор 24 МГц.

```
ПІНАУТ ПРОЄКТУ
  GPIO4  ── вхід ADC   ← дільник з фоторезистором (датчик на лобовому склі)
  GPIO5  ── вихід      → білий LED (ближнє світло), через 330 Ом
  GPIO6  ── вихід      → помаранчевий LED #1 (аварійка), через 330 Ом
  GPIO7  ── вихід      → помаранчевий LED #2 (аварійка), через 330 Ом
  GPIO8  ── вхід       ← кнопка (датчик удару) з ВНУТРІШНІМ Pull-up + 0.1 мкФ

СХЕМА — ДАТЧИК ОСВІТЛЕНОСТІ (Урок 1.6)
  3.3V ──[ LDR ]──┬──[ 10 кОм ]── GND
                  └──────────────► GPIO4 (ADC)

СХЕМА — КНОПКА «ДАТЧИК УДАРУ» (внутрішній Pull-up, Урок 1.4/1.5)
  3.3V ───(внутрішня підтяжка в ESP32)─── GPIO8 ──[ кнопка ]── GND
                                            └──[ 0.1 мкФ ]── GND
   • Не натиснуто → внутрішня підтяжка тримає GPIO8 = HIGH (1)
   • Натиснуто    → кнопка коротить пін на GND = LOW (0)
   • Конденсатор 0.1 мкФ згладжує брязкання АПАРАТНО
```

> **🔴 ТЕХНІКА БЕЗПЕКИ**
> • Кожен LED — через **свій** резистор 330 Ом (не один спільний на три діоди!).
> • Перемикаємо при **вийнятому USB**. На пін не більше **3.3 В**.
> • Конденсатор 0.1 мкФ полярності не має — вмикати можна будь-яким боком.
> • Для ADC — пін каналу ADC1 (GPIO1–10 на S3).

## 02 · Крок 1 · Адаптивне світло (тунель → ближнє) ⏱ 30 хв

> **🟢 МЕТА**
> Фара сама вмикає біле світло, коли стемніло (заїзд у тунель).

**КОД · src/main.cpp**
```cpp
// Проєкт 2 — Крок 1: адаптивна фара
#define LDR_PIN   4
#define HEAD_PIN  5            // білий LED — ближнє світло
#define TUNNEL    1500         // ← підстав СВОЄ число (темрява)

void setup() {
  Serial.begin(115200);
  pinMode(HEAD_PIN, OUTPUT);
}

void loop() {
  int light = analogRead(LDR_PIN);
  if (light < TUNNEL) {
    digitalWrite(HEAD_PIN, HIGH);     // темно → ближнє світло УВІМК
  } else {
    digitalWrite(HEAD_PIN, LOW);      // світло → фара ВИМК
  }
  Serial.println(light);
  delay(150);
}
```

> **🟣 РОЗБІР КОДУ: чому саме так, а не інакше**
> - **`analogRead` → 0..4095** — у ESP32 АЦП 12-бітний (на відміну від 10-бітного Uno), тому максимум `4095`.
> - **`if (light < TUNNEL)`** — за схемою дільника менше число = темніше, тому вмикаємо саме **нижче** порога. Це фізичний зв'язок «опір LDR → напруга → число».
> - **`TUNNEL` як `#define`** — поріг калібрується під освітлення кімнати в одному місці.
> - **`delay(150)`** — авто в реальності реагує швидко; коротка пауза тримає реакцію «живою», але не вантажить монітор.

> **🔵 ЩО СПОСТЕРІГАЄМО**
> Накрив LDR долонею («тунель») — біле світло ввімкнулось; відкрив — згасло.

> **🟠 МІНІ-ЗАВДАННЯ**
> Підбери `TUNNEL` так, щоб світло вмикалось від тіні руки, а не від звичайного освітлення.

### 🌗 Бонус · Три зони освітленості (фіксований стан білого LED)

Замість простого «увімк/вимк» зробимо **три режими** білого LED залежно від фоторезистора: **день** (світло) → вимкнено; **сутінки** (середнє) → **блимає** (авторежим/попередження); **ніч/тунель** (темно) → **постійно світить**.

**КОД · src/main.cpp**
```cpp
// Проєкт 2 — Бонус: три зони освітленості білого LED
#define LDR_PIN  4
#define HEAD_PIN 5
#define DUSK     2500          // поріг сутінків (СВІТЛІШЕ за тунель)
#define TUNNEL   1500          // поріг темряви
#define BLINK_MS 500           // напівтакт блимання в сутінках

bool on = false;
unsigned long lastBlink = 0;

void setup() {
  Serial.begin(115200);
  pinMode(HEAD_PIN, OUTPUT);
}

void loop() {
  int light = analogRead(LDR_PIN);

  if (light < TUNNEL) {                 // ТЕМНО → постійно світить (фіксований стан)
    digitalWrite(HEAD_PIN, HIGH);
  } else if (light < DUSK) {            // СУТІНКИ → блимає (неблокуюче)
    if (millis() - lastBlink >= BLINK_MS) {
      lastBlink = millis();
      on = !on;
      digitalWrite(HEAD_PIN, on);
    }
  } else {                             // ДЕНЬ → вимкнено
    digitalWrite(HEAD_PIN, LOW);
  }
}
```

> **🟣 РОЗБІР КОДУ: чому саме так, а не інакше**
> - **Два пороги, а не один** — `light < TUNNEL` (темно) і `TUNNEL ≤ light < DUSK` (сутінки). Пам'ятай: за схемою дільника **менше число = темніше**, тому пороги стоять «згори вниз»: `DUSK (2500) > TUNNEL (1500)`.
> - **`else if`, а не три окремі `if`** — гілки **взаємовиключні**: пін потрапляє рівно в одну зону. Три незалежні `if` могли б спрацювати разом і «перебивати» один одного.
> - **Блимання лише в середній зоні і на `millis()`** — у крайніх зонах `digitalWrite(HEAD_PIN, HIGH/LOW)` **фіксує** стан без блимання, а неблокуючий таймер у сутінках не «заморожує» решту коду (кнопку, аварійку).
> - **`on` і `lastBlink` оголошені поза `loop()`** — їхній стан має **зберігатися між проходами** циклу; локальні змінні обнулялися б щоразу й блимання не працювало б.

> **🔵 ЩО СПОСТЕРІГАЄМО**
> Яскраве світло — LED не горить. Прикрив трохи (сутінки) — блимає. Накрив повністю (тунель) — світить постійно. Покрути `DUSK`/`TUNNEL` під свою кімнату, спостерігаючи `light` у Serial.

> **🟠 МІНІ-ЗАВДАННЯ**
> Додай **третій поріг** і четверту зону «глибока ніч» — щоб у сутінках LED блимав повільно (1 Гц), а в повній темряві світив постійно та яскраво.

> Щоб вшити це в повний код Кроку 4 — винеси триступеневу логіку в окрему функцію `updateHeadlight()` і виклич її в `loop()` замість рядка адаптивної фари (1).

## 03 · Крок 2 · Кнопка «датчик удару»: pull-up чи pull-down? ⏱ 30 хв

> **🟢 МЕТА**
> Зрозуміти **два способи** підключити кнопку (pull-up і pull-down), навчитися читати її без «плаваючого» входу і свідомо обрати схему під свій набір деталей.

**Головне правило: схема резистора і код мусять збігатися.** Інакше логіка кнопки переплутається.

| Як підключено | Не натиснуто | Натиснуто | Режим у коді | Як читати |
|---|---|---|---|---|
| **Pull-UP** (кнопка → GND, підтяжка вгору) | HIGH (1) | LOW (0) | `INPUT_PULLUP` (внутр.) | `== LOW` |
| **Pull-DOWN** (кнопка → 3.3 В, резистор 10 к → GND) | LOW (0) | HIGH (1) | `INPUT` (зовн. рез.) або `INPUT_PULLDOWN` (внутр.) | `== HIGH` |

```
ВАРІАНТ А — PULL-UP (внутрішній, без зовнішнього резистора)
  3.3V ──(внутрішня підтяжка ~45 кОм у ESP32)── GPIO8 ──[ кнопка ]── GND
   • Відпущено → HIGH ;  Натиснуто → LOW

ВАРІАНТ Б — PULL-DOWN (зовнішній резистор 10 кОм)
  3.3V ──[ кнопка ]──┬──────────► GPIO8
                     └──[ 10 кОм ]── GND
   • Відпущено → LOW ;  Натиснуто → HIGH
```

**КОД · ВАРІАНТ А (pull-up) · src/main.cpp**
```cpp
// Проєкт 2 — Крок 2А: кнопка з ВНУТРІШНІМ pull-up (без зовн. резистора)
#define CRASH_PIN 8

void setup() {
  Serial.begin(115200);
  pinMode(CRASH_PIN, INPUT_PULLUP);   // увімкнули внутрішній резистор до 3.3 В
}

void loop() {
  // з INPUT_PULLUP: відпущено = HIGH, натиснуто = LOW
  Serial.println(digitalRead(CRASH_PIN) == LOW ? "УДАР!" : "...");
  delay(100);
}
```

**КОД · ВАРІАНТ Б (pull-down) · src/main.cpp**
```cpp
// Проєкт 2 — Крок 2Б: кнопка з ЗОВНІШНІМ pull-down (резистор 10 кОм до GND)
#define CRASH_PIN 8

void setup() {
  Serial.begin(115200);
  pinMode(CRASH_PIN, INPUT);          // підтяжку дає зовнішній резистор
  // pinMode(CRASH_PIN, INPUT_PULLDOWN); // або внутрішня pull-down, без зовн. резистора
}

void loop() {
  // з pull-down: відпущено = LOW, натиснуто = HIGH
  Serial.println(digitalRead(CRASH_PIN) == HIGH ? "УДАР!" : "...");
  delay(100);
}
```

> **🟣 РОЗБІР КОДУ: чому саме так, а не інакше**
> - **Навіщо взагалі підтяжка?** Без неї «відпущений» пін **висить у повітрі** (floating) і ловить наведення — у авто особливо. Підтяжка (зовнішня чи внутрішня) тримає чіткий відомий рівень, поки кнопку не натиснули.
> - **Pull-up: чому натиснуто = LOW?** Кнопка з'єднує пін із **GND**. Підтяжка тягне вгору (HIGH), натискання «перемагає» її → LOW. Логіка **інвертована**, тому `== LOW`.
> - **Pull-down: чому натиснуто = HIGH?** Резистор тягне пін до **GND** (LOW), а натискання подає на нього 3.3 В → HIGH. Тому `== HIGH`.
> - **🔴 НЕ ЗМІШУЙ:** якщо лишити `INPUT_PULLUP` і одночасно поставити зовнішній резистор на GND — внутрішні ~45 кОм і зовнішні 10 кОм утворять **дільник**, потече зайвий струм, рівні стануть «брудні», а читання `== LOW` зламається. Один пін — одна підтяжка.
> - **`INPUT_PULLDOWN`** — особливість саме ESP32 (на Arduino Uno такого немає): дає pull-down **без** зовнішнього резистора. Зручно, якщо хочеш «натиснуто = HIGH», але без зайвих деталей.
> - **Який обрати?** Pull-up (Варіант А) — менше деталей, це й вимагає методика проєкту (вибір піна з підтяжкою «за даташитом», Урок 1.4). Pull-down (Варіант Б) — якщо хочеш **однакову схему кнопки** у всіх трьох проєктах (у Проєктах 1 і 3 теж pull-down).

> **🔵 ЩО СПОСТЕРІГАЄМО**
> Обери один варіант, залий — у моніторі «...» змінюється на «УДАР!» при натисканні. **Підключи аналізатор** до GPIO8: для pull-up чистий HIGH провалюється в LOW (для pull-down — навпаки), а в момент контакту видно пачку брязкання.

> **🟠 МІНІ-ЗАВДАННЯ**
> Збери кнопку обома способами по черзі. Переконайся, що при зміні схеми треба міняти і режим (`INPUT_PULLUP`↔`INPUT`/`INPUT_PULLDOWN`), і умову (`== LOW`↔`== HIGH`).

> **⚠️ ВАЖЛИВО ДЛЯ НАСТУПНИХ КРОКІВ**
> Далі основний код написано під **Варіант Б (pull-down): `INPUT` + `== HIGH`** — це збігається з твоєю тактовою кнопкою та з Проєктами 1 і 3. У Кроці 4 схему можна перемкнути одним рядком (`PRESSED`/`BTN_MODE`): для **pull-up** постав `INPUT_PULLUP` + `LOW`.

## 04 · Крок 3 · Аварійна сигналізація (меандр) + аналізатор ⏱ 35 хв

> **🟢 МЕТА**
> Натискання «удару» вмикає режим аварійки: два помаранчеві LED блимають синхронно. На аналізаторі бачимо **меандр** і його частоту (Урок 1.3).

**КОД · src/main.cpp**
```cpp
// Проєкт 2 — Крок 3: адаптивна фара + аварійка
#define LDR_PIN   4
#define HEAD_PIN  5
#define HAZ1_PIN  6
#define HAZ2_PIN  7
#define CRASH_PIN 8
#define TUNNEL    1500
#define BLINK_MS  400           // період напівтакту блимання

bool hazard = false;            // режим аварійки увімкнено?
bool on = false;                // поточний стан LED аварійки
unsigned long lastBlink = 0;

void setup() {
  Serial.begin(115200);
  pinMode(HEAD_PIN, OUTPUT);
  pinMode(HAZ1_PIN, OUTPUT);
  pinMode(HAZ2_PIN, OUTPUT);
  pinMode(CRASH_PIN, INPUT);            // pull-down: зовн. 10 кОм до GND (натиснуто = HIGH)
}

void loop() {
  // 1) адаптивна фара працює завжди
  digitalWrite(HEAD_PIN, analogRead(LDR_PIN) < TUNNEL ? HIGH : LOW);

  // 2) удар вмикає аварійку (фіксуємо режим)
  if (digitalRead(CRASH_PIN) == HIGH) hazard = true;   // pull-down → HIGH

  // 3) блимання аварійки — неблокуюче, на millis()
  if (hazard && millis() - lastBlink >= BLINK_MS) {
    lastBlink = millis();
    on = !on;                       // інвертуємо стан → меандр
    digitalWrite(HAZ1_PIN, on);
    digitalWrite(HAZ2_PIN, on);     // обидва синхронно
  }
}
```

> **🟣 РОЗБІР КОДУ: чому саме так, а не інакше**
> - **`millis()` замість `delay()` для блимання** — фара та кнопка мають реагувати **під час** миготіння аварійки. `delay(400)` заморозив би все: плата не «бачила» б ні нового удару, ні зміни світла. Це головна причина перейти на таймер.
> - **`millis() - lastBlink >= BLINK_MS`** — класична неблокуюча перевірка «чи минув інтервал». Запам'ятовуємо мітку `lastBlink` і чекаємо, поки різниця дорівняє періоду.
> - **`on = !on`** — інверсія робить рівні пілку HIGH/LOW однакової тривалості → на аналізаторі це **меандр** (симетричний прямокутний сигнал). Частота = 1 / (2 × BLINK_MS) = 1/0.8 с ≈ 1.25 Гц.
> - **`hazard = true` (без вимикання)** — у реальному авто аварійка не гасне сама після удару. Скидання винесемо в челендж.
> - **Обидва LED від одного `on`** — щоб блимали **строго синхронно**; різні таймери дали б «розсинхрон».

> **🔵 ЩО СПОСТЕРІГАЄМО**
> Тиснемо «удар» — помаранчеві LED рівномірно блимають. **Аналізатор** на GPIO6: чіткий меандр; виміряй період (≈800 мс) і частоту. Зміни `BLINK_MS` — меандр стискається/розтягується.

> **🟠 МІНІ-ЗАВДАННЯ**
> За допомогою аналізатора виміряй реальну частоту блимання й порівняй із розрахунковою 1.25 Гц.

## 05 · Крок 4 · Антидребезг: програмний + конденсатор 0.1 мкФ ⏱ 25 хв

> **🟢 МЕТА**
> Зрозуміти **брязкання контактів** і два способи його прибрати: кодом і «залізом» (конденсатор 0.1 мкФ, Урок 1.1/1.5).

**КОД · src/main.cpp (ПОВНА система: фара + аварійка + дебаунс)**
```cpp
// Проєкт 2 — Крок 4: повний код з антидребезгом кнопки
#define LDR_PIN   4
#define HEAD_PIN  5
#define HAZ1_PIN  6
#define HAZ2_PIN  7
#define CRASH_PIN 8
#define TUNNEL    1500
#define BLINK_MS  400              // напівтакт миготіння аварійки

// --- НАЛАШТУВАННЯ КНОПКИ під свою схему (за замовч. pull-down) ---
const int  BTN_MODE = INPUT;       // pull-down: INPUT (зовн.10к) або INPUT_PULLDOWN
const bool PRESSED  = HIGH;        // pull-down → HIGH ;  pull-up → LOW
const unsigned long REAL_HIT_MS = 80;   // натискання має триматись > 80 мс

bool hazard = false, on = false;
unsigned long lastBlink = 0, pressStart = 0;

void setup() {
  Serial.begin(115200);
  pinMode(HEAD_PIN, OUTPUT);
  pinMode(HAZ1_PIN, OUTPUT);
  pinMode(HAZ2_PIN, OUTPUT);
  pinMode(CRASH_PIN, BTN_MODE);
}

void readCrash() {                            // дебаунс «за стабільністю»
  if (digitalRead(CRASH_PIN) == PRESSED) {    // кнопку тримають
    if (pressStart == 0) pressStart = millis();               // зафіксували початок
    else if (millis() - pressStart > REAL_HIT_MS) hazard = true;  // тривало → УДАР
  } else {
    pressStart = 0;                           // відпустили/провал брязкання → скидаємо
  }
}

void loop() {
  // 1) адаптивна фара — працює завжди
  digitalWrite(HEAD_PIN, analogRead(LDR_PIN) < TUNNEL ? HIGH : LOW);

  // 2) кнопка з антидребезгом
  readCrash();

  // 3) аварійне МИГОТІННЯ (меандр), поки активна тривога
  if (hazard && millis() - lastBlink >= BLINK_MS) {
    lastBlink = millis();
    on = !on;                       // інверсія → симетричний меандр
    digitalWrite(HAZ1_PIN, on);
    digitalWrite(HAZ2_PIN, on);     // обидва синхронно
  }
}
```

> **🟣 РОЗБІР КОДУ: чому саме так, а не інакше**
> - **Що таке брязкання (bounce)?** Механічні контакти при дотику кілька мілісекунд «дзвенять» — пін стрибає HIGH↔LOW багато разів. Без фільтра одне натискання може зчитатися як десятки подій.
> - **Дебаунс «за стабільністю»** — реагуємо не на першу появу рівня `PRESSED`, а на те, що пін **стабільно** утримується довше за `REAL_HIT_MS` (80 мс). Брязкання триває одиниці мс, тож кожен його провал скидає `pressStart`, і поріг не досягається. Один параметр (80 мс) водночас прибирає брязкання **і** відсіює короткий шум/наведення (Урок 1.5).
> - **`pressStart == 0` як «прапорець не запущено»** — нуль означає «відлік ще не почато». Так одним рядком розрізняємо «щойно притиснули» і «тримають далі»; при відпусканні відлік скидається в 0.
> - **`PRESSED` і `BTN_MODE` зверху** — одним рядком перемикають код між **pull-down** (`HIGH`/`INPUT`, стоїть за замовчуванням — твоя схема) і **pull-up** (`LOW`/`INPUT_PULLUP`), не чіпаючи логіку всередині.
> - **Миготіння — окремо від кнопки.** `hazard` лише **вмикається** в `readCrash()` (з фіксацією), а сам меандр генерує блок (3) у `loop()` на `millis()`. Тому фара й кнопка реагують навіть **під час** блимання — це і є відповідь «так, миготіння при ударі є й воно неблокуюче».
> - **Конденсатор 0.1 мкФ (апаратний дебаунс)** паралельно кнопці утворює з підтяжкою **RC-фільтр**: ємність не дає напрузі стрибати миттєво (τ = R × C), згладжуючи брязкання ще **до** піна. Ставиться між піном і GND — однаково для pull-up і pull-down.
> - **Чому показуємо обидва способи?** На аналізаторі видно: без конденсатора — пачка імпульсів; із 0.1 мкФ — чистий плавний фронт. Це доводить, навіщо елемент із Уроку 1.1.

> **🔵 ЩО СПОСТЕРІГАЄМО**
> Канал 1 аналізатора — на пін кнопки, канал 2 — на пін LED. **Без** конденсатора видно брязкання та хибні спрацювання; **з** 0.1 мкФ фронт стає чистим, а програмний фільтр прибирає залишки. Коротке торкання (шум) більше не вмикає аварійку — лише впевнене натискання.

> **🟠 МІНІ-ЗАВДАННЯ**
> Зніми осцилограму кнопки з конденсатором і без нього. Виміряй тривалість «дзвону» в обох випадках.

## 06 · Контроль, діагностика та челенджі

> **🔧 ЯКЩО ЩОСЬ НЕ ПРАЦЮЄ**

| Симптом | Причина / рішення |
|---|---|
| Аварійка вмикається сама | Немає підтяжки (floating) або кнопка «дзвенить» — увімкни `INPUT_PULLUP`/`INPUT_PULLDOWN`, застосуй дебаунс / конденсатор |
| Кнопка реагує навпаки | Схема (pull-up/pull-down) не відповідає коду — звір режим піна й умову `== LOW`/`== HIGH` (Крок 2) |
| Кнопка взагалі не реагує | Переплутані ноги кнопки (вона має 2 пари з'єднаних) або не той пін |
| Один помаранчевий не блимає | Анод/катод, відсутній 330 Ом, поганий контакт у ряду |
| Фара реагує навпаки | Знак нерівності `<`/`>` не відповідає схемі дільника |
| Блимання «плаває» | Використано `delay` — переходь на `millis()` |

> **🏆 ЧЕЛЕНДЖІ ДЛЯ ШВИДКИХ**

| # | Завдання |
|---|---|
| 1 | **Скидання аварійки:** довге утримання кнопки (>1.5 с) вимикає `hazard`. |
| 2 | **Поворотники:** ліва/права кнопка блимає лише своїм боком. |
| 3 | **Денні ходові огні:** удень білий LED світить тьмяно через ШІМ, у тунелі — на повну. |
| 4 | **«Біжуча» аварійка:** помаранчеві LED вмикаються по черзі, а не синхронно. |
| 5 | **Лічильник ударів:** виводь у Serial, скільки разів спрацював датчик. |

## 07 · Словник коду та термінів (шпаргалка викладача)

| Конструкція / термін | Що означає |
|---|---|
| `INPUT_PULLUP` | Режим входу з вбудованим резистором підтяжки до 3.3 В; натиснута кнопка дає LOW. |
| `INPUT_PULLDOWN` | Режим входу з вбудованим резистором підтяжки до GND (особливість ESP32); натиснута кнопка дає HIGH. |
| **Pull-up / підтяжка вгору** | Резистор до 3.3 В: «відпущений» вхід = HIGH, натиснуто = LOW. |
| **Pull-down / підтяжка вниз** | Резистор до GND: «відпущений» вхід = LOW, натиснуто = HIGH. |
| **Floating (плаваючий вхід)** | Невизначений стан піна без підтяжки — ловить наведення. |
| **Брязкання / bounce** | Багаторазові хибні перемикання контакту в перші мс натискання. |
| **Дебаунс** | Усунення брязкання — програмно (`millis()`) або апаратно (конденсатор). |
| **RC-фільтр** | Резистор + конденсатор; згладжує швидкі стрибки напруги (τ = R×C). |
| **Конденсатор 0.1 мкФ** | Ємність, що «гасить» брязкання апаратно (Урок 1.1). |
| **Меандр** | Симетричний прямокутний сигнал (HIGH і LOW однакової тривалості). |
| `millis()` | Мс від старту — основа неблокуючого блимання та таймерів. |
| `a ? b : c` | Тернарний оператор — короткий `if/else` для виразу. |
| `!on` | Логічне заперечення — інверсія стану (увімк↔вимк). |
